# PhotoBench 错误分析与报告（规则版本 3）

错误分析为测评结果的派生读模型，不写回原分数、GT、Agent预算和恢复策略。入口为运行详情的“错误分析”，默认先展示全部题目的回答结果与分类表现。普通测评/重评分收尾后自动排队，历史记录手动生成；失败、取消、中断和仅构建相册的运行也可分析，后者仅报告导入与处理阶段。

## 分层与生命周期

- `domain/error_analysis/rules.py`：分类、去重题数、逐轮行为、覆盖分组、检索信号、逐题配对。`exports.py`输出离线HTML及JSON/CSV。
- `application/error_analysis/service.py`：自动触发、显式选择分析provider；通过`AnalysisBackend`端口编排。
- `infrastructure/error_analysis/backend.py`：结果根目录下`.analysis/<job_id>`持久化任务、案例索引和报告，单个spawn子进程，最多32个待执行任务。新测评/重评分优先，执行中的分析在逐题检查点暂停。AI单次请求最长60秒，无法撤回已经发出的请求；取消确认仍以工作退出为准。
- `worker.py`：读取已提交JSONL，先固定私有输入，逐题分析、保存轻量案例；不在HTTP请求或遥测采样线程加载原始轨迹。老式仅run.json结果在隔离子进程内兼容读取。导出扫描轻量索引，完整原始轨迹按需通过既有逐题接口读取。
- `bootstrap/container.py`唯一构造依赖；API与前端只操作任务和派生产物。

测评/评分与受管采样收尾→释放原工作→排队分析→固定输入→规则聚合→提交完成状态。分析失败、取消、中断不会改变原run终态。分析任务进入`active-work`、`cancel-active`和服务退出确认。重启将遗留活跃任务标记`interrupted`，用户可以重试，不假装已完成。

报告记录规则版本、生成时间、源代码版本、结果SHA256、GT指纹、源文件修订和覆盖情况。结果、元数据或重新评分变化会标记过期，旧产物保留。新对比和AI任务拒绝使用过期规则报告；已生成的对比/诊断也随来源过期。原始轨迹接口始终返回当前保存事实，旧报告排查时须先核对来源。

## 统计与证据

质量分数0/1/2/缺分、执行正常/失败/取消/未知、评分故障分别统计；题数、对话轮、模型调用、工具调用、已记录参数JSON各有独立分母。每类异常保存事件数、受影响题数、最终执行失败题数及明确恢复题数，类别允许重叠。

上下文软预算预检、窗口超限、输出空间不足、输出截断和未知子类分开；工具参数非法、模型格式错误、服务响应JSON错误和Judge输出错误分开。`parse_failure`没有证据时归未知解析失败。历史文本识别标记`legacy_text`；结构化记录优先。事件引用包含题索引、轮次、步骤、角色和调用ID。恢复只认同轮同角色同一步重试成功等明确证据，最终回答成功不自动证明所有异常已恢复。

题型、任务类型、难度、角度、可回答性、预期行为、媒体类型、单/多轮分别报告。多标签分组可重叠；未覆盖行为不算0%正确，未知标签不补造。逐轮行为筛选同时要求预期与实际在同一轮匹配。

检索有GT才判断候选未命中；候选命中未交付、交付后低分分别展示，均为定位信号。源报告还显示阶段错误、保存错误、遥测完整分量与有效样本数；缺失历史数据保留未知。

## 新调用事实采集

主Agent、规划器和Judge追加可选诊断字段及唯一逻辑调用ID。`RecordedPhotoInspector`是可选观测端口，以调用局部ContextVar收集工具内部模型的请求、超时、格式、HTTP及token事实；保留原inspect接口和原失败回退。预算采用调用前已经计算的估计值及响应usage，不重新制定预算。不改变提示词、重试、压缩或恢复策略。旧记录缺字段保持未知；一次逻辑调用内的底层HTTP重发尚未全部展开为独立transport attempt。

## API契约

均在`/api/v1`，类型见OpenAPI `AnalysisJob/AnalysisReport/AnomalyEvent/CaseReference/CasePage/ComparisonReport/DiagnosisReport`。

| 接口 | 用途 |
|---|---|
| POST `/runs/{run_id}/analysis` | `kind=rules/compare/ai`创建后台任务；202 |
| GET `/runs/{run_id}/analysis` | 最新规则任务及报告、过期标记 |
| GET `/runs/{run_id}/analyses` | 历史任务，保留旧来源 |
| GET `/analyses/{job_id}` | 任务进度与完成报告 |
| POST `/analyses/{job_id}/cancel` | 请求取消，工作查询确认退出 |
| GET `/analyses/{job_id}/cases` | 分页，按异常类别/题目形式/任务类型/角度/难度/可回答性/媒体/对话/行为/分数/恢复/执行状态筛选 |
| GET `/analyses/{job_id}/export?format=html/json/csv` | 来源、统计、筛选条件和案例摘要；不默认附完整轨迹 |

JSON/CSV/HTML的案例筛选使用同一规则。报告图表为全样本统计、案例为筛选命中，页面及导出明确区分。HTML无CDN依赖，使用原生条形图/表格/折叠案例；所有原始文本转义，CSV防止公式执行。交互页面使用已有ECharts并按需读取原始步骤。主视图按2分答对、1分部分答对、0分答错及未评分分组；答对率仅使用有效Judge题数为分母。任务类型默认使用已保存task_type（媒体检索、事实问答、统计枚举、事件总结），可切换题目形式、角度、难度等维度；未知标签保留，前端不按题目文本猜分类。运行异常及逐轮行为放进阶排查，不与回答对错相加。

## 两轮对比

以非重复QA ID及题目、GT和逐轮对话定义指纹配对；缺ID/重复ID、定义变化、单边未匹配单列。展示质量变化、执行状态变化和异常新增/消失。Judge配置/已记录系统提示词指纹与预算不一致或缺少关键配置时，不给出“版本提升”汇总。设备、模型、代码版本差异保留，不作因果归因。

## 按需AI诊断

默认关闭。用户选择1–20题并明确确认provider后，复用既有Judge配置；秘密只在父进程内存和子进程参数中传递，不写任务文件。并发1，超过20题分批启动。诊断输出观察、可能原因、缺少证据、修改建议、验证实验及证据引用；引用必须属于本案例，否则标无效。轨迹内的指令是被分析数据。AI不能重评分、改GT、改事实分类。无效结果可查看原文，不作为有效建议展示。

首版不包含跨多轮历史趋势、自动修Agent、自动重评分或PDF/Word。案例摘要文本单字段最多8000字并标记截短；完整轨迹保留原接口。大报告导出为显式同步操作，只扫描派生索引；规则分析和模型请求全部在受管子进程中。

## 结果浏览与操作便利性（2026-10-24）

案例与HTML/JSON/CSV导出共享`task_type/angle/difficulty/answerability/media_type/conversation_type`过滤；`score=low`只包含0/1分，不含未评分；`anomaly=yes/no`只描述是否有已记录事件。旧查询兼容。规则版本3在逐题提取时按明确别名统一任务类型，同题重复别名先去重，再汇总；筛选与导出沿用同一分类。原始QA和GT指纹保留原值，版本2旧报告标记过期并保留，重新生成新报告。

AI支持全选本页、选择当前筛选前20题、未完全答对题和运行异常题；选择不发模型请求。下一批可跳过本报告本次会话中已有效诊断案例，单批仍≤20；跨页选择可见计数，切换过滤/报告清空选择。模型仍需显式选择并确认。

两轮对比从分页历史运行下拉选择，按日期/模型/题集搜索已加载记录，可加载更早记录；排除本轮、活跃运行和仅构建任务。另一轮缺报告或报告过期时，通过现有后台规则任务自动准备，完成后再创建对比；准备失败显示原因，停止等待不取消共享规则任务。对比方向固定为“所选另一轮相对当前基准”，关键配置不全时仍不作版本提升结论。

任务类型中的`T1_retrieve_media/T1_media_retrieval/media_retrieval/媒体检索`统一为`T1_retrieve_media`。其他明确别名见domain的`taxonomy.py`，不按题目内容推断。显示名称统一简洁中文，`behavior`为“行为判断”。主页面保留结果卡片和分类堆叠图，移除重复结果图及阅读说明；统计定义、检索细节折叠，只有多标签重叠时提示。窄柱段不强行排数字，表格与悬浮仍提供完整数值。
