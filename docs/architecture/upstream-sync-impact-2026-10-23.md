# 上游同步影响检查

## 结论

本地 `asr` 分支已从 `497bfcf` 快进到原作者仓库 `upstream/main@8fb29cc`，共纳入 80 个提交。上游没有新增或替代音频 ASR、转写存储、FTS 或音频分段向量能力，因此我们现有音频方案仍然需要保留。

同步涉及 202 个文件，主体是 PhotoBench 指标与遥测、部署稳定性、导入进度、视频 SVD 场景规划和健康诊断。与音频链路直接相交的冲突只有 4 处，均已合并为“保留上游能力 + 保留音频能力”。

## 与当前工作相关的上游新增能力

- 导入进度现在有独立领域模型、进程内存储和 API，未来可以把音频 ASR 阶段纳入统一导入进度，但本次未擅自扩展范围。
- API 新增线程上限，能降低重负载下事件循环被 CPU 算子饿死的风险；ASR 仍在独立 sidecar 中，不会把大模型直接加载进 API 进程。
- 视频新增 SVD 场景规划，未来“视频场景切分 → 音轨 ASR → 时间轴对齐”可以复用这些场景窗口；当前音频实现仍按 ASR 分段时间戳保存。
- PhotoBench 的遥测和运行时拓扑大幅增强，但尚未登记 ASR sidecar 为独立受测服务；如果以后比较生产链路资源，需要补一条 ASR 服务遥测归属。
